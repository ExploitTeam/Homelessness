# Правки MAX-бота, выпуск 2

Этот архив дополняет предыдущую версию с фондами, несколькими менеджерами и журналом броней.

## Изменения

1. **Создание фонда.** Исправлена обработка событий: одно входящее сообщение обрабатывает только один обработчик. Название и описание отправляются **двумя разными сообщениями**. Описание можно пропустить, введя `-`. Лимит описания — 1500 символов.
2. **Удаление фонда.** Администратор бота или администратор **именно этого фонда** может запустить удаление из карточки фонда. Перед удалением показываются количество пунктов и активных броней, кнопки отмены и подтверждения. Подтверждение удаляет фонд, все его пункты и связи менеджеров, закрывает активные брони, отзывает роли администраторов удаляемого фонда. **История броней и события остаются в базе**, пользователям закрытых броней отправляются уведомления. Обратной операции нет. Не удаляйте фонд, если хотите сохранить его пункты — сначала перенесите их в другой фонд от имени глобального администратора.
3. **Управление пользователями.** У администраторов пункт меню называется «Управление пользователем», у менеджеров и посетителей — «Настройки профиля». Глобальный администратор может выбрать пользователя по MAX ID, назначить администратором конкретного фонда или снять эту роль; в карточке фонда есть быстрые кнопки отзыва прав. Администратор фонда не может выдавать глобальные права или права на чужой фонд.
4. **Публичная информация.** MAX ID менеджеров не выводятся в карточках помощи, брони и обычном профиле; остаются в служебных разделах персонала там, где необходимы для поиска/управления. При отсутствии телефона выводится «Номер телефона не указан». Номер **брони** сохраняется, чтобы на неё можно было ссылаться.
5. **Разделение пунктов по фондам.** «Управление пунктами» → фонд → пункт. Глобальный администратор видит все фонды и пункты; администратор фонда — только свой фонд; менеджер — фонды с назначенными ему пунктами. Проверки повторяются на каждом действии, в том числе при использовании старых кнопок.
6. **Кнопки менеджеров.** В привязках используются короткие названия с метками `➕`/`✅`, расшифровка вынесена в текст сообщения; длинные подписи ограничены.
7. **Markdown.** Подключён параметр `format: "markdown"` на уровне отправки и редактирования MAX-сообщений. Разметка используется только в карточках пунктов, фондах, профилях, истории/бронях и приветствии. Пользовательские данные экранируются. Прочие сообщения остаются обычным текстом.
8. **Номера броней.** Добавлена таблица `booking_ids` с монотонной последовательностью SQLite `AUTOINCREMENT`. Старые номера резервируются при миграции. Удаление активных броней и истории не освобождает номера. Повторно создать запись со старым ID нельзя.

## Установка

1. Остановите бота и API. **Сделайте резервную копию рабочей `.env` и `database.db`.**
2. Распакуйте этот архив поверх предыдущего кода, **сохранив свою** `.env` и `database.db`. В поставке базы нет.
3. Запустите `python main.py` либо `docker compose up -d --build`.
4. При запуске `initialize_database()` добавит таблицу `booking_ids` и зарезервирует прежние номера. Остальные миграции выполняются повторно безопасно.
5. Проверьте: «Фонды» → создать → указать название → отдельным сообщением указать описание; затем роль администратора фонда, меню пунктов, брони и историю.

## Тесты

```bash
python -m unittest discover -s tests -v
python -m compileall -q main.py maxbot database
```

Тесты работают на временных базах, не изменяя вашу `database.db`.

## Границы изменений и предупреждения

- **API и папка `Web/` не изменялись.** Сайт мини-приложения продолжает использовать прежнее поле `manager_info` и может показывать только одного менеджера, в отличие от интерфейса бота. При необходимости исключить IDs также из ответов API и интерфейса мини-приложения потребуется **отдельная** правка: здесь сохранён прежний API-контракт.
- При удалении фонда его пункты и активные брони действительно исчезают. Сохраняются только история/события и сведения о пользователях; делайте резервную копию перед опасной операцией.
- Роли администраторов, прописанных в `MAX_ADMINS_ID` в `.env`, защищены и не могут быть сняты из бота.
- Верификация выполнена по официальной документации MAX: [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages), [редактирование сообщений](https://dev.max.ru/docs-api/methods/PUT/messages), [форматирование текста](https://dev.max.ru/docs-api/use-cases/sending-messages/text-formatting).
- Доставка через реальный MAX и отображение на устройствах требуют проверки в работающем боте с действующим токеном.
