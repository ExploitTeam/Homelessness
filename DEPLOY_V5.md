# Почему мини-приложение MAX не обновилось — проверка публикации v5

В v4 исходники фронтенда и `Web/dist` были обновлены, однако **публикация сайта на адресе MAX не выполняется распаковкой архива**. MAX открывает именно тот HTTPS URL, который записан в настройках бота. Если ваш сайт живёт на другом хостинге, перезапуск Docker с ботом не заменит файлы на том хостинге.

## 1. Определите реальный URL мини-приложения

В кабинете [MAX для партнёров](https://business.max.ru/) перейдите **Чат-боты → ваш бот → ⋮ → Настройки → URL мини-приложения**. Запишите точный адрес. Это **не обязательно** адрес API. Подробнее: https://dev.max.ru/help/miniapps

## 2. Если мини-приложение обслуживается тем же Docker-контейнером

В каталоге **реально запущенного проекта**:

```sh
# До замены: резервное копирование, обязательно сохраните .env и database.db!
cp database.db database.backup.$(date +%Y%m%d-%H%M%S).db

# После копирования исходников v5 (не перезаписывайте .env и database.db):
docker compose up -d --build --force-recreate app

# Убедитесь, что новая сборка действительно внутри контейнера:
docker compose exec app cat /app/Web/dist/index.html | grep v5-20261019
```

Если команда не находит `v5-20261019`, обновили **не тот каталог** проекта / не тот контейнер.

Проверьте по внешнему URL, указанному у бота (замените адрес на свой):

```sh
curl -fsS https://ВАШ-ДОМЕН/api/version
curl -sI https://ВАШ-ДОМЕН/ | grep -i cache-control
curl -fsS https://ВАШ-ДОМЕН/ | grep v5-20261019
```

Ожидается `"release":"v5-20261019"`, `"frontend_marker":true`, заголовок `Cache-Control: no-store` и ссылка на `/releases/v5-20261019/src/main.js`.

## 3. Если сайт размещён отдельно от бота/API (Nginx, CDN, другой VPS или статический хостинг)

Необходимо **загрузить содержимое `Web/dist/` на веб-хостинг, указанный в MAX**, в его реальный корневой каталог. Одного обновления контейнера API недостаточно. Проверьте, что `https://АДРЕС-САЙТА/` выдаёт `max-miniapp-version=v5-20261019` в исходном HTML и доступны файлы по `/releases/v5-20261019/...`.

Если API не на том же домене, укажите в `Web/index.html` до сборки, или в готовом `Web/dist/index.html`:

```html
<meta name="max-api-base-url" content="https://homelessness.bot.nu" />
```

Значение `content` должно быть **фактическим адресом вашего API**, без пути `/api` в конце. По умолчанию приложение запрашивает API с того же домена, что и сайт.

Настройте на внешнем веб-сервере **отсутствие кэша для `/` и `/index.html`**, а каталоги `/releases/v5-20261019/` допустимо кэшировать долго. При использовании CDN сбросьте кэш HTML после загрузки.

## 4. MAX

Если поменяли домен/URL сайта, в настройках бота MAX измените URL мини-приложения. Если URL прежний и на нём **уже загружена v5**, сохраните прежний URL. Закройте мини-приложение и откройте вновь. В левом верхнем углу карты теперь видна небольшая метка `v5`.

Если `/api/version` возвращает **404 или прежнюю версию**, вы обращаетесь к старому процессу, другому серверу или прокси/CDN. Если `/api/version` показывает v5, а HTML всё ещё старый, проверьте маршруты Nginx и кэш: API и HTML раздаются из разных мест. Если HTML уже v5, но интерфейс старый, проверьте вкладку Network (файлы `/releases/v5-20261019/`) и наличие ошибок в консоли браузера.

## 5. Что изменено в v5

- Стабильные уникальные пути к JS/CSS `/releases/v5-20261019/...` (предотвращают повторное использование старых модулей).
- HTML отдаётся сервером FastAPI с `Cache-Control: no-store`.
- Диагностический `/api/version` без авторизации.
- Незаметная метка `v5` на карте, которую легко использовать для проверки обновления.
- API по умолчанию берётся с домена мини-приложения. При отдельном хостинге настраивается `max-api-base-url`.
- Карточка v4 (фонд, описание, менеджеры, закреплённые кнопки) сохранена.
- Рабочие `database.db` и `.env` в архив не входят.

**Важно:** установка архива на локальном компьютере не может автоматически обновить удалённый сервер, к которому у нас нет доступа. Не путайте тестовую страницу/проект и опубликованный URL в MAX.
