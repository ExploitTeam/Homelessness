# Версия 4 — мини-приложение и API

## Новое отображение пункта

В карточке на карте находятся отдельные разделы:

1. **Название категории и адрес** — в верхней части карточки.
2. **Основные сведения** — статус пункта (работает / не работает), расстояние по прямой, свободные места, график работы.
3. **Организация** — отдельный блок с названием фонда и полным описанием (с сохранением переносов строк).
4. **О пункте** — дополнительная информация именно об этом пункте, не смешивается с описанием фонда.
5. **Моя бронь** — видна только при существующей активной брони текущего пользователя; дата и статус читаемые.
6. **Контакты пункта** — все назначенные менеджеры, имена и номера телефонов. Если номера нет, написано «Номер телефона не указан». Служебные MAX ID отсутствуют.
7. **Как добраться** — сворачиваемый раздел с маршрутом Московского метро, если построение маршрута возможно.

Кнопки **«☎️ Контакты»** и **«Забронировать»** постоянно видны внизу развернутой карточки, независимо от прокрутки длинных описаний. Первая перемещает к контактам, вторая создаёт бронь, если имеются свободные места и бронь ещё не создана. После бронирования данные обновляются.

## API

`GET /api/places` (JWT обязателен) теперь включает:

```json
{
  "id": 1,
  "address": "Москва, улица Примерная, 10",
  "fund": {
    "name": "Фонд поддержки",
    "description": "Описание фонда"
  },
  "category_label": "Ночной приют",
  "managers": [
    {"name": "Анна", "phone": "+7 900 000-00-00"},
    {"name": "Сергей", "phone": null}
  ],
  "manager_info": {"username": "Анна", "phone_number": "+7 900 000-00-00"},
  "booking": {}
}
```

Пример показывает **дополнительные поля**: фактический ответ также содержит адрес, координаты, режим работы, категории, сведения о местах и другие прежние поля. `fund` может быть `null`, если у пункта не указан фонд. `booking` содержит только активную бронь авторизованного пользователя либо `{}`. Поля `manager_info` и `booking` оставлены для совместимости; `manager_info` больше не содержит чужие ID, роли или служебные поля. Данные выдаются только после проверки MAX initData и JWT (как и ранее).

`POST /api/book` по-прежнему бронирует пункт. Один вызов `Bot.send_msg` на первого менеджера уже автоматически отправляет новую заявку всем остальным менеджерам пункта, поэтому двойная рассылка исключена.

Изменены `openapi.yaml` и `DATA-API.yaml`. **Миграция базы не требуется.**

## Установка

1. Сделать резервные копии `database.db` и `.env` из текущего проекта.
2. Заменить код проекта содержимым архива, оставив свои `.env` и `database.db`.
3. В архиве уже находится актуальная сборка фронтенда `Web/dist` (не нужно собирать её при установке).
4. Перезапустить сервис: `docker compose up -d --build`.
5. Проверить в MAX пункт с длинным описанием, несколько менеджеров, переход к контактам, отправку брони.

Для последующей разработки фронтенда: из каталога `Web` выполнить `npm ci && npm run build`. Дополнительно приложена команда `node build_no_native.cjs` для автономной ESM-сборки в окружениях, где недоступен нативный компонент Vite, при условии что `node_modules` уже установлены. Все библиотеки содержатся в `Web/dist`, внешнего CDN для React/MapLibre не требуется.
